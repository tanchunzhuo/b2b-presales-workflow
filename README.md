# B2B 售前工作流

> 把复杂 B2B 销售中「必须做、但极其耗时」的四件售前工作，固化成可重复的流程。
>
> **它不替销售做判断，只负责把信息整理到人可以快速判断的程度。**

## 这是什么

四个模块，四份可评审的售前材料：

| 模块 | 输出物 | 手工耗时（估算） | 用后（估算） |
| --- | --- | --- | --- |
| 客户背景研判 | 客户画像卡 | 半天到一天 | 约 30 分钟 |
| 需求假设与验证 | 假设清单 + 验证问题 | 半天 | 约 40 分钟 |
| 竞品参数对照 | 对照表 + **劣势应答** | 一天 | 约 1.5 小时 |
| 分角色拜访方案 | 五角色沟通方案 | 一天 | 约 1 小时 |

> **关于耗时数字**：以上为基于流程拆解的**估算，非实测数据**。估算依据是各环节的信息检索量与文档产出量。实际效果取决于使用者的行业经验与信息可得性。**未做 A/B 实测，在此明确说明。**

## 三个设计决定

这三条是本项目和一般"销售提示词合集"的区别所在。

### 1. 强制标注「待核实」

大模型在生成采购记录、金额、人名、职务时，有较高概率产出**看似合理实则不存在**的信息。这不是可以忽略的缺陷，是必然特性。

所以所有模块强制要求：无法确认的一律标 `⚠️ 待核实`，并给出核实方法。

**宁可交一份有空白的资料，也不要交一份掺假的。** 客户一句「你说的这个项目我们没有」，信任就没了。

### 2. 强制写出己方劣势

竞品对照模块**必须列出至少 3 条明确弱于对手的地方**。

售前材料只写优势，等于让销售在客户提问时裸奔。客户问「你们和 XX 比这块弱一点」，没准备的销售只有两种反应：硬撑（当场不被信）或语塞（当场丢分）。

**准备好的劣势应答，比多列三条优势有用。**

### 3. 假设必须标证据强度

需求假设分三级：合规政策推导（强）/ 客户公开信息推导（中）/ 行业普遍规律（弱）。

**弱证据的假设不得在客户面前当事实说。**

这个分级逼使用者区分「我知道」和「我猜」——**这是新手和老手最大的差别。**

## 快速开始

### 方式一：直接用（零成本）

打开任意大模型对话窗口，粘贴对应模块的提示词，填入变量。

```
1. 复制 prompts/01-client-profile.md 中的提示词
2. 填入客户公司名、我方产品
3. 用 templates/client-profile.md 校对输出格式
```

### 方式二：装成 Skill（Claude Code / Codex / Cursor 等）

```bash
curl -fsSL https://raw.githubusercontent.com/tanchunzhuo/b2b-presales-workflow/main/install.sh | bash
```

安装后直接说：`研判一下 XX 公司` 或 `帮我准备下周的客户拜访`。

### 方式三：手动安装

```bash
git clone https://github.com/tanchunzhuo/b2b-presales-workflow.git
cp -r b2b-presales-workflow ~/.claude/skills/
```

其他平台对应目录见 `docs/PLATFORM_ADAPTERS.md`。

## 行业包机制

**不同行业的决策链、采购流程、合规约束差异极大。通用模块给骨架，行业包给血肉。**

```
industry-packs/
└── healthcare-cn.md    中国公立医院（六角色、政府采购、评级体系）
```

加载行业包会**覆盖**默认的角色定义、采购流程、合规红线与需求驱动因素。

### 以医疗行业包为例，它覆盖了什么

通用模型说「五个角色」，医疗包说**六个**——多出来的是**纪检监察**。评标委员会名单需纪委签字，开标在纪检监督下进行。**这个角色你不需要沟通，但不知道他存在的销售，在客户眼里就是外行。**

通用模型说「决策层拍板」，医疗包说**分管院长不能拍板**，他的作用是推动项目上**院长办公会集体决策**。说「搞定分管院长这个项目就成了」，一句话暴露外行。

**每个行业包都必须标注信息来源与可信度等级。** 见 `docs/CONTRIBUTING.md`。

**欢迎 PR 新的行业包**——制造业、金融、政企、教育、零售，都缺。

## 完整示例

`examples/walkthrough-manufacturing.md` 用一个虚构的制造业客户，把四个模块完整跑通，含最终商务判断。

这个示例刻意做了三件事：

1. **记录了 4 处人工修正**——包括 AI 编造 2 条无法验证的采购记录、技术负责人推翻 1 条参数判断
2. **假设清单里有 1 条对我方不利的假设**
3. **最终结论是「不建议投入重点资源」**

> **一个只会输出「建议积极跟进」的工具没有价值。**

## 它能做什么，不能做什么

**能做的**：把可公开检索的信息，按 B2B 售前的实际需要整理成可用的结构。

**不能做的**：

- **不能替代销售经验。** 判断哪条信息重要，靠的是人。
- **不能获取非公开信息。** 而 B2B 最关键的信息往往不公开：现有供应商的服务口碑、部门之间的真实关系、这笔预算真正的推动者、上一个项目为什么失败。
- **不能保证准确。** 大模型会编造具体信息，所有关键信息必须人工核实。
- **不能替代技术判断。** 参数比对表是初稿，最终判断必须由技术人员做。**一条参数判断错误，可能导致废标。**

**一句话**：它让一个懂业务的销售，把花在找资料、做表格、写初稿上的时间压缩掉，把省下的时间用来见客户。**它不会让一个不懂业务的人变成懂业务的人。**

详细局限性见 `docs/LIMITATIONS.md`。

## 关于作者与这个项目的由来

我做过十三年 B2B 商务与生态合作，跨过四个行业。这套工作流是我在梳理自己的售前流程时做出来的。

**医疗行业包不是因为我做过医院销售——我没做过。** 它是一次公开信息研究的产物：从零开始拆解一个陌生行业的采购决策链，然后做了一轮完整的事实核查，**自查出 7 处行业事实错误并全部修订**。

所以行业包里的每一条事实都标了来源和可信度等级，也明确写了「本包全部为 B 级，未逐条查阅官方原始文件全文」。

**如果你是任何一个行业的从业者，看到与实际不符的地方，请提 Issue。** 具体到「哪一条、实际是怎样、依据是什么」最好。会改，并注明修订来源。
