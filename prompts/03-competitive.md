# 模块三：竞品对照与参数分析

## 用途

1. 拿到招标文件或需求清单，快速判断参数是否有指向性、我方是否满足
2. 生成参数对照表和差异化应对话术，**包含我方劣势的应答准备**

---

## 提示词

```
你是 B2B 售前技术顾问。

【输入】
项目名称：{{}}
采购方式：{{公开招标 / 竞争性磋商 / 竞争性谈判 / 询价 / 单一来源 / 商务议标}}
参数清单：{{粘贴招标文件技术参数部分或需求清单}}
我方参数：{{}}
已知竞品：{{可选}}

【任务】

一、参数逐条比对
| 序号 | 参数要求 | 星号/权重 | 我方状态 | 差距说明 | 应对方式 |
状态分：完全满足 / 部分满足 / 不满足 / 需定制开发
输出：总符合率 + 实质性条款（星号项）符合率

二、指向性识别
识别可能指向特定供应商的参数，逐条说明识别依据。
注意：政府采购与国企采购要求需求书客观、无排他性。
指向性参数可作为质疑依据，但是否质疑是商务决策，不在本模块判断范围。

三、采购方式适配分析
- 公开招标：参数符合率是门槛，价格权重通常较高
- 竞争性磋商：方案与响应能力权重高，可多轮调整
- 竞争性谈判：价格敏感
- 单一来源：若供应商非我方，评估是否继续投入
- 商务议标：关系与方案并重，早期介入价值最大

四、我方劣势清单（强制项，至少 3 条）
必须列出明确弱于竞品的地方。
每条给出应答思路，不得回避、不得虚构优势掩盖。

五、差异化话术
分角色输出：业务负责人 / IT / 决策层 / 采购
每个角色 2-3 句，语言符合该角色关注点。

【禁止】
- 禁止编造竞品缺陷
- 禁止贬低性表述
- 禁止对未实现功能做承诺
- 禁止推测竞品报价
```

---

## 为什么强制写劣势

售前材料只写优势，等于让销售在客户提问时裸奔。

客户问「你们和 XX 比，这块好像弱一点」，销售如果没准备，只有两种反应：硬撑（客户当场不信）或语塞（当场丢分）。

**准备好的劣势应答，比多列三条优势有用。**

### 劣势应答的三种写法

**一、转移到场景**

> 「是的，在纯 X 场景下他们的方案更成熟。我们的优势在 Y 场景。如果贵司这块的主要压力在 Y，我们的适配度会更好。您这边 X 和 Y 的比重大概是？」

**前提：这个转移必须真实。如果客户的压力真在 X，就不要硬转。**

**二、给替代方案**

> 「这个功能我们当前版本确实没有。但同样的目标，我们可以用 Z 方式实现，需要额外 N 天对接。如果这是必要项，我可以出一个具体方案给您评估。」

**前提：Z 方案必须技术上确实可行，且承诺的工期必须能兑现。**

**三、向内部提出放弃建议**

> 「这个项目参数里有三条是我们明确不满足的硬性指标，且短期内无法补齐。建议评估是否投入。」

**注意：这是一线销售向内部提出的建议，不是自行决定放弃。**

是否参与投标由销售负责人或商务负责人决定。一线的职责是把真实情况反馈上去，不是替公司做决策。

**在实际组织里，一线擅自决定放弃项目是越权行为。**

---

## 指向性参数的四个特征

| 特征 | 说明 |
| --- | --- |
| 参数值异常精确 | 如「响应时间 ≤ 0.37 秒」，非行业通用刻度 |
| 组合条件苛刻 | 单项都常见，但同时满足只有一家 |
| 绑定特定认证 | 要求某项非强制的特定认证或专利 |
| 业绩要求过窄 | 如「近三年 X 家同类案例且单个金额 ≥ Y」 |

**识别之后怎么办，不是这个模块决定的。**

可能是调整投标策略、可能是提出质疑、也可能是判断为不可竞争后放弃。**这是商务判断，涉及客户关系与公司策略，AI 不做建议。**

**这个模块只负责把事实摆清楚。**

---

## 使用提醒

**技术参数的最终判断必须由技术人员做。**

AI 输出的比对表是初稿，用于缩短技术人员的审阅时间，**不能直接作为投标依据**。

**一条参数判断错误，可能导致废标或中标后无法履约。这个环节不存在「差不多就行」。**
