# 如何贡献

最需要的贡献是**新的行业包**。

---

## 为什么需要行业包

通用模块给的是骨架：五个角色、通用采购流程、通用提问结构。

但真实的 B2B 销售里，**决定成败的是行业特有的那部分**：

- 制造业的决策链和金融业完全不同
- 政企采购有招投标法约束，民企没有
- 强监管行业（医疗、金融）有独特的合规红线
- 每个行业的「最硬的预算理由」都不一样

**通用模块给骨架，行业包给血肉。**

---

## 行业包必须包含的六部分

参照 `industry-packs/healthcare-cn.md` 的结构：

### 1. 角色模型（覆盖通用五角色）

如果你的行业有额外角色（如医疗行业的纪检监察），必须写出来，并说明**为什么销售需要知道他存在**。

表格必须含：角色 / 核心关注 / 决策权重 / 最反感 / **常见误区**。

最后一列最有价值——它直接告诉使用者哪句话会暴露外行。

### 2. 决策链路

用流程图描述从需求发起到合同签订的完整路径，标注：

- 每个环节由谁负责
- 关键的金额门槛（如「超过 X 万须上会」）
- 哪些环节有否决权

**必须明确写出：这个行业里，是否存在「单一角色可以拍板」的情况。** 多数情况下答案是否定的，而这正是新手最容易判错的地方。

### 3. 需求驱动因素

这个行业里，**最硬的预算理由**是什么？

合规强制？上级考核？成本压力？业务增长？技术债务？

如果有评级、认证、资质类的强制要求，详细写出来——**这通常是最好的切入点**。

### 4. 合规红线

这个行业里，什么话不能说、什么信息不能碰。

### 5. 商业现实（可选但强烈建议）

**这一节是为了让使用者不要对行业有错误预期。**

比如：客户有没有钱？付费意愿如何？商业模式跑通了吗？

如果这个行业存在「客户想要但付不起」的结构性问题，写出来。**这比多写十条话术有用。**

### 6. 信息来源与可信度声明

**这一节是硬性要求，没有它的 PR 不会被合并。**

必须包含：

- 每类事实的来源类型与可信度等级（A/B/C/D）
- 如果你不是该行业从业者，**明确写出来**
- 明确标出哪些内容是 C 级（仅作定性参考）
- 如果没查过 A 级原始文件，说明这个局限

---

## 可信度分级标准

| 级别 | 含义 |
| --- | --- |
| **A** | 官方原始文件：部委发文、法规原文、上市公司公告、官方统计 |
| **B** | 权威机构或专业媒体解读，且多来源交叉一致 |
| **C** | 单一来源的行业观察或从业者经验分享 |
| **D** | 来源不明或无法交叉验证 |

**规则**：
- C 级内容可以写，但必须标出，且不得用于定量判断
- **D 级内容一律不收录**
- 有时效性的数据（如统计数字、通过家数）必须标统计时点

## 提交流程

1. Fork 本仓库
2. 在 `industry-packs/` 下新建 `<行业>-<地区>.md`（如 `manufacturing-cn.md`）
3. 按上述六部分撰写
4. 在 `README.md` 的行业包列表里加一行
5. 提 PR，在描述里说明：**你是不是这个行业的从业者**

---

## 关于「我不是这个行业的从业者，能贡献吗」

**能，但必须如实声明。**

本仓库的医疗行业包就是非从业者做的——它的价值不在于「作者是专家」，而在于：

- 每条事实标了来源和可信度
- 明确写出了作者没做过这行
- 经过一轮完整事实核查，自查出并修正了 7 处错误
- 主动邀请从业者指错

**如实标注来源的外行内容，比不标来源的内行内容更可用。** 因为前者可以被验证和修正，后者不能。

## 其他贡献方式

- **指出错误**：提 Issue，具体到「哪一条、实际是怎样、依据是什么」
- **补充模板**：如果你有更好用的输出模板
- **平台适配**：补充 `docs/PLATFORM_ADAPTERS.md` 中新平台的安装路径
