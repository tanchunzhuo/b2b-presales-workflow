# 模块四：分角色拜访方案

## 用途

一次 B2B 拜访通常要见多个角色。这个模块为每个角色生成独立的沟通方案。

---

## 先说清楚决策链

**这是整套工作流里最容易出错、也最能暴露外行的地方。**

### 复杂 B2B 采购的典型决策链路

```
1. 需求发起
   业务部门提出需求，需说明业务价值与预期收益

2. 内部评估
   IT/技术部门评估可行性、对接成本、安全合规
   采购部门核查供应商资质
   财务核定预算科目与付款条件

3. 审批
   按金额分级审批。达到一定额度需上会集体决策
   ⚠️ 金额门槛各公司不同，必须问清楚

4. 采购执行
   按金额与项目性质确定方式：
   公开招标 / 竞争性磋商 / 竞争性谈判 / 询价 / 单一来源 / 商务议标

5. 评审与定标
   国企、上市公司通常有内控与审计要求
   部分组织有纪检/合规部门全程监督

6. 合同与履约
   合同签订、验收、付款节点
```

### 三个必须记住的结论

**第一，多数中大额采购不由单一角色拍板。**

「搞定 X 总这个项目就成了」——这句话在多数正规组织里是错的，说出口会被听出是外行。**你要找的不是"能拍板的人"，是"愿意在内部推动这件事的人"。**

**第二，被绕过的部门几乎必然让项目卡住。**

尤其是 IT 和采购。他们通常不能推动项目成立，但有事实上的否决权。

**第三，部门名称各公司不同。**

IT 部 / 信息中心 / 数字化部 / 技术中台 / 信息技术中心——统称「技术部门」是外行标志。

**正确做法：早期就问「贵司这类项目是哪个部门牵头？」这个问题本身显得专业，而且答案直接决定你后续找谁。**

## 提示词

```
你是 B2B 售前顾问，为一次客户拜访准备分角色沟通方案。

【输入】
客户：{{公司}}
拜访对象：{{列出角色与姓名，姓名可留空}}
拜访目的：{{初次接触 / 需求确认 / 方案汇报 / 参数沟通 / 投标前沟通}}
已有信息：{{画像卡与假设清单摘要}}
时长：{{分钟}}
行业包：{{若已加载，在此声明}}

【任务】
为每个角色输出：

1. 该角色在本项目中的实际作用
   （基于集体决策链，不得写成个人拍板）
2. 开场（3 句以内，不推销）
3. 必问问题（3-5 个，开放式）
4. 必答准备（该角色最可能问的 3 个问题及回答要点）
5. 需要传递的关键信息（不超过 3 条）
6. 本次成果判定（一句可验证的话）
7. 禁区（对该角色不能说的话）

【时间分配】
按重要性给出建议分钟数，总和不超过时长

【全局禁止】
- 禁止编造已有客户案例
- 禁止承诺未实现的功能
- 禁止承诺中标
- 禁止在任何角色处使用「搞定」「拿下」式内部语言
```

## 五角色开场示范

### 对业务负责人（需求方）

> 「X 总，我知道您时间紧，我今天不讲产品。我想问三个问题，了解一下 XX 这个环节现在是怎么走的。如果我们这边有能帮上的地方，我下次带方案来；如果帮不上，我也不占用您时间。」

**为什么这样开场**：业务负责人每周被多家供应商拜访。明确说「不讲产品、只问三个问题、帮不上就走」，是唯一能换到时间的方式。

**成果判定**：他说出了至少一个具体的业务困难，并且同意下次见面。

**禁区**：不要一上来讲降本。降本常常不是他的考核项，甚至他的团队会因此被裁。

### 对 IT / 技术方

> 「我们的系统需要对接 XX，接口按标准协议出。想先了解贵司目前的架构情况，以及数据安全这块有什么要求，我们提前对齐，避免后面返工。」

**为什么这样开场**：IT 最怕的是又多一套需要维护的系统、对接时反复扯皮、出事要背锅。**先谈对接和安全，是唯一能建立信任的开局。**

**成果判定**：他愿意说出现有架构的实际情况，或提出具体技术疑问。

**禁区**：绝不能说「这个我们直接和业务部门谈就行」。**绕过 IT 是重大失误，且他有事实上的技术否决权。**

### 对决策层

> 「X 总，占用您十分钟。我们看了贵司在 XX 方面的规划，如果按 YY 的要求，ZZ 这块可能是个缺口。我们在这块有对应能力，想听听您怎么看这个优先级。」

**为什么这样开场**：决策层的时间以分钟计。**开场必须直接连到他的考核项。**

**成果判定**：他明确了这件事在他心里的优先级，或指定了对接人。

**禁区**：不讲功能细节。不要说「这个项目您定了就行」——**这句话既不符合实际流程，也会让人不适。** 正确表达是「如果您认可，我们准备材料配合走内部流程」。

### 对采购

> 「我们想了解贵司这类项目的流程要求，需要准备哪些资质材料，以及一般的时间节奏。我们按您的要求准备，尽量不给您添麻烦。」

**为什么这样开场**：采购的核心诉求是**流程不出瑕疵**。表现出懂流程、配合流程，比讲任何产品优势都有用。

**成果判定**：拿到明确的材料清单和时间节点。

**禁区**：不催进度，不打听评标信息，不询问其他投标方情况。

### 对财务

> 「关于报价结构，我们想先确认一下贵司这类采购通常走什么预算科目，是一次性还是分期，这样我们的报价单可以按您的口径出。」

**成果判定**：明确了预算科目、付款节奏和报价单格式要求。

**禁区**：不做模糊报价，不承诺「后期可以谈」。

## 会后 24 小时纪要

**要求当次拜访后 24 小时内完成。**

隔夜记忆会自动美化对话内容，这是销售普遍存在的认知偏差。纪要模板中「客观记录」一栏**只写客户原话，不写自己的解读**，就是为了对抗这一点。

模板见 `templates/meeting-notes.md`。
