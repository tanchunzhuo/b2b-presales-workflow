# 局限性与信息来源

> 建议在使用本工作流之前先读完这一页。

---

## 一、四条硬性局限

### 1. 不替代销售经验

判断哪条信息重要、客户那句话是什么意思、这个项目该不该投，靠的是人。

**本工作流能做的是让一个有经验的人少花时间在整理上。它不会让没经验的人变成有经验的人。**

### 2. 公开信息有天花板

B2B 最关键的信息通常不公开：

- 现有供应商的实际服务口碑
- 部门之间的真实关系与历史恩怨
- 这笔预算真正的推动者是谁
- 上一个项目为什么失败
- 决策层内部的分歧在哪

**这些只能靠人跑出来。工作流做的是把可检索的部分快速处理掉，好让人有时间去跑不可检索的部分。**

### 3. 大模型会编造具体信息

**这不是偶发缺陷，是必然特性。** 风险最高的四类：

| 高风险内容 | 为什么危险 |
| --- | --- |
| 采购记录与中标金额 | 客户一句「我们没这个项目」，信任归零 |
| 人员姓名与职务 | 叫错名字或职务，当场出局 |
| 资质与认证信息 | 涉及投标资格，错了可能废标 |
| 技术参数满足情况 | 错判可能导致中标后无法履约 |

所以模块一强制要求标注来源和 `⚠️ 待核实`。

**看到具体数字，一律回原始渠道核对。**

### 4. 技术判断不可省

参数比对表是初稿，用于缩短技术人员的审阅时间，**不能直接作为投标依据**。

**这个环节不存在「差不多就行」。**

## 二、关于耗时数字

README 中的「手工半天 → 用后 30 分钟」是**基于流程拆解的估算，不是实测数据**。

估算依据：各环节的信息检索量与文档产出量。

**未做 A/B 实测。** 实际效果取决于使用者的行业经验与信息可得性。

## 三、信息来源与可信度分级

行业包中的所有事实必须标注可信度等级：

| 级别 | 含义 | 使用限制 |
| --- | --- | --- |
| **A** | 官方原始文件（部委发文、法规原文、上市公司公告） | 可直接引用 |
| **B** | 权威机构或专业媒体解读，多来源交叉一致 | 可用，但关键条款建议回查 A 级原文 |
| **C** | 单一来源的行业观察或从业者经验分享 | **仅作定性参考，不用于定量决策** |
| **D** | 来源不明或无法交叉验证 | **不引用** |

### 现有行业包的自我声明

**`healthcare-cn.md`（中国公立医院）**：

- 全部事实为 **B 级**
- 作者**未做过医院销售**，内容来自公开资料检索与交叉验证
- 作者**未逐条查阅 A 级原始文件全文**，这是明确的局限
- 包内标出了 3 条 C 级内容，明确说明它们「影响了对客户动机的理解，但未作为任何具体判断的依据」
- 本包为 v2，v1 → v2 修正了 **7 处行业事实错误**（修订记录见包内末尾）

## 四、合规提醒

### 通用

1. 所有对外材料必须经人工审核后使用
2. 不得包含通过非公开途径获得的信息
3. 不得编造客户案例
4. 不得承诺未实现的功能
5. 不得对招标结果做任何暗示或承诺

### 涉及国企、政府采购、上市公司时额外注意

- 采购流程通常有内控与审计要求
- 部分组织有纪检/合规部门全程监督
- 不打听评标信息、不在开标前接触评委、不做任何形式的利益输送
- **所有沟通留痕合规**

### 涉及强监管行业（医疗、金融、教育等）

各行业有各自的宣传与广告约束。**使用对应行业包前，请先确认自己了解该行业的合规边界。**
